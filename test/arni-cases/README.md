# Тест трёх кейсов курса в Arni

Три кейса с автоматической проверкой результата. Агент работает в интерфейсе Arni, человек только ставит задачу и отвечает на запросы разрешений. Скрипт проверки сам решает, выполнен ли кейс.

| № | Кейс | Папка проекта | Проверок | Изображения |
|---|---|---|---:|---|
| 1 | [Договор по реквизитам](contract-kz/README.md) | `C:/work/test-arni-contract` | 32 | желательно (просмотр PDF) |
| 2 | [Лендинг курса](landing/README.md) | `C:/work/test-arni-landing` | 24 | обязательно |
| 3 | [Обновление презентации](pptx-update/README.md) | `C:/work/test-arni-pptx` | 17 | обязательно |

Промпт каждого кейса — в его README. Копировать его целиком, без правок.

## 1. Подготовка, один раз

1. Установить Arni Code **1.0.13**: [ArniCodeSetup.exe](https://github.com/ssadkov/arni-code/releases/download/v1.0.13-xlsx-test/ArniCodeSetup.exe). Перед установкой полностью закрыть Arni.
   - Это последняя сборка. Она включает медиаплеер из 1.0.7, исправление XLSX и уточнённый выбор моделей.
   - Сборка сделана из ветки PR #34, которая ещё не влита в `main`.
2. В админке Arni:
   - импортировать каталог Bedrock, чтобы появились модели из PR backend #6;
   - в карточке своего пользователя разрешить `global.anthropic.claude-haiku-4-5-20251001-v1:0` и `qwen.qwen3-vl-235b-a22b`;
   - проверить, что денежный бюджет не исчерпан.
3. На компьютере должны быть:
   - Python 3 с `python-docx`, `python-pptx`, `pypdf`;
   - Microsoft Word — PDF договора;
   - PowerPoint — превью слайдов;
   - Node.js — проверка лендинга.

   Если чего-то нет, агент должен сам сказать об этом; это тоже результат теста.
4. Проекты уже созданы. Чтобы начать кейс с чистого листа, удалить его папку и собрать заново:

   ```bash
   python test/arni-cases/contract-kz/build_project.py C:/work/test-arni-contract
   ```
   ```bash
   python test/arni-cases/landing/build_project.py C:/work/test-arni-landing
   ```
   ```bash
   python test/arni-cases/pptx-update/build_project.py C:/work/test-arni-pptx
   ```

## 2. Прогон одной модели на одном кейсе

1. File → Open Folder → папка кейса.
2. Новый чат.
3. Выбрать модель под полем ввода.
4. Вставить промпт из README кейса и отправить.
5. Не подсказывать. Разрешения на браузер, команды и запись файлов — давать. Если агент задаёт вопрос, ответить коротко и записать, что он спросил.
6. Дождаться финального ответа агента. Если он завис дольше 10 минут без движения — остановить и записать «завис».
7. Command Palette → «Arni: Расходы API в USD» → «Текущий чат». Записать сумму, число запросов и токены «из кэша».
8. Запустить проверку кейса, см. раздел 4.
9. Переименовать `output` в `output-<модель>`, например `output-haiku`. Иначе следующая модель перезапишет результат, а проверка требует ровно один файл в `output/`.

Порядок: Haiku 4.5, затем Qwen3 VL, на каждом кейсе. Каждая модель — в новом чате, чтобы история не переносилась.

## 3. На что смотреть глазами

Скрипт не видит следующих вещей:

- **Смотрел ли агент картинки на самом деле.** В истории чата должен быть вызов просмотра изображения. Фраза «я проверил скриншот» без такого вызова — провал.
- **Не выдумал ли он данные.** В договоре ФИО директора исполнителя должно остаться пустым, и агент должен об этом сказать.
- **Общий вид.** Открыть `output/` и посмотреть:
  - PDF договора;
  - `desktop.png` и `mobile.png` лендинга;
  - `preview/*.png` презентации.
- **Сколько ошибок агент исправил сам** и правдив ли его итоговый отчёт.

## 4. Проверка результата

Запускать из папки `C:/work/arni-code`, пока результат лежит в `output/`:

```bash
python test/arni-cases/contract-kz/check.py C:/work/test-arni-contract
```
```bash
node test/arni-cases/landing/check.mjs C:/work/test-arni-landing
```
```bash
python test/arni-cases/pptx-update/check.py C:/work/test-arni-pptx
```

Скрипт выводит JSON: сколько проверок пройдено и какие провалены. Код выхода 0 — кейс пройден полностью.

Если запускать скрипты некогда, достаточно переименовать папки `output-<модель>` и прислать список прогнанных моделей: проверку можно сделать за вас.
