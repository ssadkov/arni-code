# Тест трёх кейсов курса в Arni

Три кейса с автоматической проверкой результата. Агент работает в интерфейсе Arni, человек только ставит задачу и отвечает на запросы разрешений. Скрипт проверки сам решает, выполнен ли кейс.

| № | Кейс | Код кейса | Проверок | Изображения |
|---|---|---|---:|---|
| 1 | [Договор по реквизитам](contract-kz/README.md) | `contract-kz` | 32 | желательно (просмотр PDF) |
| 2 | [Лендинг курса](landing/README.md) | `landing` | 24 | обязательно |
| 3 | [Обновление презентации](pptx-update/README.md) | `pptx-update` | 17 | обязательно |

**Каждый прогон — в своей чистой папке.** В общей папке агент находит скрипты и результаты прошлой модели и переиспользует их. Так 2026-10-30 Kimi K2.5 запустила скрипт, оставленный Nemotron, и проверка засчитала чужую работу.

## 1. Подготовка, один раз

1. Установить Arni Code **1.0.13**: [ArniCodeSetup.exe](https://github.com/ssadkov/arni-code/releases/download/v1.0.13-xlsx-test/ArniCodeSetup.exe). Перед установкой полностью закрыть Arni.
2. В админке Arni:
   - «Модели Bedrock» → «Загрузить каталог», если страница показывает модели, которых нет в базе;
   - в карточке своего пользователя разрешить нужные модели, например `moonshotai.kimi-k2.5`, `global.anthropic.claude-haiku-4-5-20251001-v1:0`, `qwen.qwen3-vl-235b-a22b`;
   - проверить, что денежный бюджет не исчерпан.
3. На компьютере должны быть:
   - Python 3 с `python-docx`, `python-pptx`, `pypdf`;
   - Microsoft Word — PDF договора;
   - PowerPoint — превью слайдов;
   - Node.js — проверка лендинга.

   Если чего-то нет, агент должен сам сказать об этом; это тоже результат теста.

## 2. Прогон одной модели на одном кейсе

1. Из папки `C:/work/arni-code` создать папку прогона:

   ```bash
   python test/arni-cases/new_run.py contract-kz kimi-k2.5
   ```

   Первый аргумент — код кейса, второй — короткая метка модели для имени папки. Скрипт:
   - создаёт `C:/work/arni-runs/<кейс>-<модель>-<дата-время>`;
   - печатает промпт и команду проверки;
   - на Windows копирует промпт в буфер обмена.
2. File → Open Folder → эта папка. Новый чат, выбрать модель.
3. Вставить промпт и отправить. Промпт не менять: результат всегда в `output/` своей папки.
4. Не подсказывать. Разрешения на браузер, команды и запись файлов — давать. Если агент задаёт вопрос, ответить коротко и записать, что он спросил.
5. Дождаться финального ответа агента. Если он завис дольше 10 минут без движения — остановить и записать «завис».
6. Command Palette → «Arni: Расходы API в USD» → «Текущий чат». Записать сумму, число запросов и токены «из кэша».
7. Запустить команду проверки, которую напечатал `new_run.py`.

Следующая модель или повтор — снова `new_run.py`. Старые папки не трогать: в них остаётся результат для сравнения.

## 3. На что смотреть глазами

Скрипт не видит следующих вещей:

- **Смотрел ли агент картинки на самом деле.** В истории чата должен быть вызов просмотра изображения. Фраза «я проверил скриншот» без такого вызова — провал.
- **Не выдумал ли он данные.** В договоре ФИО директора исполнителя должно остаться пустым, и агент должен об этом сказать.
- **Общий вид.** Открыть `output/` папки прогона и посмотреть:
  - PDF договора;
  - `desktop.png` и `mobile.png` лендинга;
  - `preview/*.png` презентации.
- **Сколько ошибок агент исправил сам** и правдив ли его итоговый отчёт.

## 4. Проверка результата

Запускать из папки `C:/work/arni-code`:

```bash
python test/arni-cases/contract-kz/check.py C:/work/arni-runs/<папка прогона>
```
```bash
node test/arni-cases/landing/check.mjs C:/work/arni-runs/<папка прогона>
```
```bash
python test/arni-cases/pptx-update/check.py C:/work/arni-runs/<папка прогона>
```

Скрипт выводит JSON: сколько проверок пройдено и какие провалены. Код выхода 0 — кейс пройден полностью.

Если запускать скрипты некогда, достаточно прислать названия папок прогона: проверку можно сделать за вас.
