## Понятные задачи на существующем контексте

| Сценарий | Вход | Результат | Основная проверка |
|---|---|---|---|
| Помощник по мероприятиям | Город, период, тема, требования пользователя | 3–5 мероприятий: дата, время/часовой пояс, место, аудитория, условия участия, первичная ссылка | Актуальные даты, совпадение страницы мероприятия с формой, неизвестные явно отмечены |
| Подбор грантов/акселераторов для Arni или Yield AI | Подтверждённое описание проекта и ограничения | Таблица подходящих программ, дедлайнов, условий, необходимых документов | Действующий набор, eligibility по официальным условиям, без выдуманных достижений и обещания одобрения |
| Проверка материала для Crypto_rentier | Текст или 3–5 тезисов | Таблица «утверждение / первоисточник / подтверждено, опровергнуто или неизвестно / правка» | Источники действительно прочитаны; мнение и рекламное утверждение не выдаются за факт |
| Сравнение инструментов для монтажа | Одна операция и одинаковые критерии | 3 инструмента: ОС, нужная функция, ограничения, условия использования, ссылка | Сравнивается одна задача; отсутствие данных не заменяется догадкой |
| Сравнение затрат моделей | Проверенные тарифы и обезличенная выгрузка usage | Таблица фактических расходов, оценки альтернатив и отдельного эффекта кеша | Фактическая модель с fallback, дата тарифа, оценка не выдаётся за реальное списание |

Первый демонстрационный цикл: найти мероприятие → сверить условия и форму → подготовить запись в таблице → заполнить форму после разрешения на передачу указанных данных. Редактирование Excel включать в этот цикл после отдельной проверки помощника; первый браузерный тест может сохранить CSV/Markdown. Не смешивать все новые возможности в одном непроверенном прогоне.

## Excel: первая версия проверяемого сценария

В просмотренной встроенной библиотеке Arni нет отдельного навыка Excel. Общая возможность запускать локальный Python не доказывает корректное редактирование произвольной книги. Возможности Excel-инструментов среды Codex автоматически в Arni не появляются.

Предлагаемая профессия: «Аналитик», модель выбирается отдельно. Предлагаемые навыки `spreadsheet-inspect`, `spreadsheet-clean`, `spreadsheet-report` и `web-research` / `form-assistant` пока являются планом, а не опубликованной библиотекой. Повторить подход медиа: ограниченный Python-помощник, явный план, техническая проверка, отчёт и сохранение исходников. Сами инструкции навыка можно распространять существующим backend-каталогом; зависимости, движок пересчёта формул и интерфейс предварительного просмотра требуют отдельного решения и проверки, а не только загрузки текста навыка.

Минимальный объём:

1. Прочитать CSV/XLSX: показать листы, размер, колонки, формулы, пропуски и типы данных без отправки всей книги в контекст модели.
2. Сделать копию результата. Сохранить идентификаторы как текст, особенно BIN, номера телефонов и значения с ведущими нулями; не превращать их в даты или числа автоматически.
3. Применить согласованные правила очистки и объединения, показать неоднозначные строки. Дубли удалять только по заданному ключу; одно имя само по себе не доказывает дубль.
4. Подготовить фильтры, итоги, понятные формулы и лист происхождения данных со ссылками и датой проверки. Для реестра из интернета каждая строка должна вести к своему источнику.
5. Проверить количество строк, суммы, формулы и сохранность входных файлов. Обычная библиотека записи XLSX не равна Excel-движку вычисления: пересчёт и совпадение показанных итогов проверять отдельно.

Для начала ограничиться обычными XLSX/CSV без макросов, внешних подключений, сложных сводных таблиц и защищённых книг. Форматирование и наличие объектов проверять после сохранения, не обещать сохранение всех особенностей произвольного файла. Содержимое ячеек — данные, не инструкции агенту; импортируемые значения не должны незаметно становиться формулами или внешними ссылками.

Первый воспроизводимый тест: два синтетических файла по 20–50 строк с известными дублями, пустыми полями, датами и идентификаторами с ведущими нулями. Задача: объединить, очистить по заданным правилам, добавить итоговый лист и журнал изменений. Приёмка сравнивается с заранее известным ответом, включая контрольные суммы и исключения. Затем тот же сценарий на разрешённой обезличенной пользовательской таблице. Лишь после этого расширять до финансовых отчётов и массового заполнения форм.

## Общий протокол

Начать с доступной бесплатной модели, умеющей вызывать инструменты; для проверки скриншотов нужна поддержка изображений. Проверять реально обслужившую модель с учётом fallback. При неудаче повторить тот же ограниченный тест дешёвой платной моделью в пределах заранее согласованного бюджета. Записывать время, запросы, стоимость, вмешательства пользователя и конкретные ошибки. Финансовые данные и личные контакты для первого теста заменять синтетическими; реальную передачу данных в форму разрешать отдельно с указанием получателя и полей.
