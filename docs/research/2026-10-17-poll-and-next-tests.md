Полезные идеи из разделов «Как нейросеть монтирует», «Безопасная зона кадра» и монтажного промпта:

- Сначала расшифровка и план сокращения, затем короткий результат с проверкой склеек. Сохранять карту исходного и выходного времени, исходники и список исправленных слов.
- Проверять, что при удалении пауз не обрезаны согласные, вдохи и смысл. Порог паузы и отступы из гайда рассматривать как исходную гипотезу для конкретной записи, не как универсальное правило.
- Проверять субтитры после монтажа: они должны соответствовать новой временной шкале, не пересекать склейки, оставаться читаемыми и не закрывать лицо.
- Собирать кадры на склейках и во время надписей, а не только равномерную таблицу кадров. Отдельно прослушивать спорные границы: статичный кадр не доказывает отсутствие обрезанного слова.
- Добавить проверку размещения текста с накладкой безопасных зон. Указанные в гайде проценты — его рекомендации для вертикального ролика; актуальность интерфейса площадки отдельно не проверялась. Не менять ориентацию видео без запроса.
- Отчёт должен содержать длительности до/после, реально выполненные операции и оставшиеся дефекты, а не только сообщение об успешном FFmpeg.

### Сопоставление с текущей библиотекой

Проверено по текущим исходникам `video-story-edit`, `video-subtitles`, `media-toolkit` и [описанию профессий](../profession-library.md).

| Идея | Текущее состояние Arni | Как тестировать |
|---|---|---|
| Смысловое сокращение и удаление повторов | Есть планирование агентом по расшифровке и применение сохранённых интервалов; нет автономного детектора всех неудачных дублей | Небольшой известный фрагмент, проверка смысла человеком |
| Расшифровка с повторным использованием | Есть локальный whisper.cpp и кеш транскрипции; другой движок, чем faster-whisper из гайда | Повторно использовать неизменную расшифровку; не переустанавливать ASR ради этого теста |
| Обычные субтитры | Есть SRT/VTT и вшивание через libass | Проверить кириллицу, длинные строки, склейки и новую временную шкалу |
| Пословная подсветка | Помощник не выравнивает отдельные слова и не делает караоке | Отдельная будущая функция; не обещать её в первом тесте |
| Плавные наезды и динамическая графика | Нет готового сценария наездов; вставки пока статичные | Отдельный этап после стабильного базового монтажа |
| Голос и музыка | Есть нормализация до -16 LUFS / -1.5 dBTP; автоматического фонового музыкального микса нет | Не обещать -14 LUFS и музыкальное приглушение из гайда без доработки |
| Проверка экспорта | Есть декодирование, длительность, кадры, звук и отчёт | Дополнить ручной оценкой, не выдавать технический успех за оценку качества |

Remotion/HyperFrames можно изучить позже для анимированной графики; установка и интеграция сейчас не выполнялись, инструкции гайда по продуктам отдельно не проверялись. Полный готовый проект автора в PDF не приложен. Указание «обучен на роликах» не является доказательством fine-tuning. CapCut остаётся вне согласованного объёма.

### Следующий ограниченный медиа-тест

После успешного greenscreen-preview полезнее проверить разговорное видео, чем сразу добавлять всю графику. Вход: разрешённый для выбранного провайдера фрагмент 20–30 секунд с одной длинной паузой и известным повтором; если есть проверенная расшифровка, приложить её.

Первый запуск: бесплатная доступная модель с изображениями, профиль «Монтажёр». Сначала краткий план сокращения; при неоднозначности смысла дождаться решения пользователя. Затем предпросмотр 10–15 секунд, обычные субтитры, исходная ориентация и голос. Максимум одна коррекция. Новая папка результата, исходники сохраняются. Без музыки, пословной анимации, нового движка ASR и полного экспорта.

Приёмка: сохранён смысл, нет обрезанных слов, субтитры совпадают с новым временем, кириллица читается, лицо не закрыто; просмотрены кадры всех склеек и прослушаны их границы. Сохранены plan/edit-map, SRT, MP4, технический отчёт. Зафиксированы время всего диалога отдельно от рендера, число запросов, фактически обслужившие модели с учётом fallback, токены и списанная API-стоимость. Нулевая цена API не означает отсутствия нагрузки на локальный компьютер. При провале той же входной задачи сравнить с дешёвой платной моделью, не меняя одновременно сценарий и исходник.

## Что тестировать следующим: браузер или книгу

Рекомендация: следующая основная проверка — поиск и сравнение в браузере, затем заполнение формы. Её непосредственно поддерживают ответы 74% и 58%. Документы/данные с 60% — второе сильное направление; книгу стоит использовать как конкретный документный тест, а не считать отдельно подтверждённым спросом.

| Очередь | Проверка | Измеримый результат |
|---|---|---|
| 1 | Браузер: найти и сравнить информацию на 3–5 первичных сайтах | Таблица по одинаковым критериям, прямые ссылки, дата проверки, неизвестные явно отмечены, каждое существенное утверждение проверяемо |
| 2 | Браузер: заполнить локальную тестовую форму данными из подготовленной таблицы | Все поля совпадают с исходником; форма оставлена черновиком без отправки; агент показывает результат и сообщает о блокирующих входе/капче |
| 3 | Документ: глава книги или PDF на 10–20 страниц | Тезисы с проверяемыми страницами, короткие цитаты, различение слов автора и выводов агента, ответы на контрольные вопросы и явные неизвестные |
| 4 | Контент-редактор: превратить проверенный материал в публикационные черновики | Согласованная фактура, разные форматы площадок, ссылки, без автоматической публикации |

Конкретный браузерный кейс: найти три инструмента для заданной рабочей задачи по официальным сайтам и заполнить таблицу «что делает / ограничения / ОС / условия использования / ссылка». До старта выбрать задачу и фиксированные критерии, чтобы заранее знать проверяемые ответы. Не смешивать первый поиск с оплатой, регистрацией, реальной заявкой или сложным личным кабинетом. Форму сначала проверять на синтетических данных в контролируемом стенде; это ещё не доказательство работы на произвольном внешнем сервисе.

Общий протокол: одинаковый запрос и входные данные, новый чат для каждой модели; сначала бесплатная, затем дешёвая платная при необходимости. Проверять доступность именно нужных инструментов: способность читать картинки сама по себе не даёт модели браузер, а наличие браузера не гарантирует успешный поиск или заполнение формы. Записывать фактические модели, стоимость, время, ошибки, число исправлений и результат ручной приёмки. Лимит платного сравнения согласовать перед запуском.

Можно отдельно дать этот короткий гайд как быструю пробу чтения PDF, но одна длинная страница не проверяет навигацию по целой книге. Полноценный тест книги должен включать несколько глав или заранее выбранный многостраничный фрагмент, таблицу/рисунок при наличии и вопросы, ответа на которые в тексте нет.
