# Медиа в чате и бесплатный монтаж — 17 октября 2026

## Подтверждённый тест на Windows, Arni Code 1.0.6

В проекте `C:\work\test-arni-greenscreen` профиль «Монтажёр» использовал
`greenscreen-preview` 1.0.2. Получен `output/free-01/preview.mp4`:
1920×1080, 5 секунд видео / 125 кадров, H.264, исходный звук AAC stereo.
Все технические проверки помощника пройдены; локальный рендер занял 9,824 с,
полный запуск помощника — 13,685 с. Это не время всего диалога.
Пользователь просмотрел ролик и подтвердил хороший результат.

Серверный `UsageLog`, выбранный по этому чату, подтвердил 13 запросов и
`costMicros = 0` во всех строках, итого **$0 API**:

| Фактически обслужившая модель | Запросы | Входные токены | Выходные токены | Стоимость |
| --- | ---: | ---: | ---: | ---: |
| `xingchen-agi/xing4.0-29b-a4b:free` | 9 | 400 564 | 1 694 | $0 |
| `dots-studio/dots-3-note-preview:free` | 4 | 182 984 | 1 534 | $0 |

В интерфейсе и локальном SDK-журнале была выбрана
`nvidia/nemotron-3.5-super-vl:free`. Во всех серверных строках это
`requestedModel`, а не фактически обслужившая модель. Backend использовал
существующую маршрутизацию недоступных бесплатных моделей; кандидаты для
запросов с изображениями фильтруются по поддержке изображений.
Нельзя приписывать этот результат качеству Nemotron. Цена подтверждена
серверным учётом (`accounting = reported`); локальные вычисления и электричество
в сумму API не входят.

Остаётся отдельная задача интерфейса: показывать фактически обслужившую модель
при серверной замене, сохраняя отдельно выбор пользователя.

## Изменения после 1.0.6

Реализовано в исходниках; в опубликованный установщик 1.0.6 эти изменения не входят.

- В Arni отключено приглашение «Sign in to Copilot», в том числе при пустом
  каталоге во время запуска. Это не скрывает ошибки запросов и не создаёт модели.
- Полный абсолютный локальный путь в inline code или markdown-ссылка на MP4,
  WebM, M4V, MP3, WAV, OGG/OGA, M4A, FLAC превращается в кнопку воспроизведения.
  Кодовые блоки с командами, относительные пути и сетевые URL не преобразуются.
- Нажатие открывает плеер в редакторной вкладке того же окна. На отрисовке чата
  файл не загружается и воспроизведение не запускается. Работает существующее
  ограничение встроенного браузера на доверенные локальные папки.
- Явные пользовательские `chat.editorAssociations` имеют приоритет.
  Файловые ссылки и артефакты используют тот же выбор редактора.
- Исправлены ответы локального `file://` для медиа: Electron выдавал часть файла
  с HTTP 200 без метаданных диапазона. Плееру нужны 206, `Content-Range`,
  `Content-Length` и `Accept-Ranges` для чтения метаданных и перемотки.
  Данные остаются потоковыми; большой ролик не загружается целиком в память.
- Декодирование зависит от контейнера и кодеков. Проверен реальный H.264/AAC MP4;
  поддержка всех сочетаний кодеков не заявляется. macOS в этом изменении ещё
  не проверялась на устройстве.

## Проверки

- TypeScript клиента: успешно.
- Electron: проверки баннера, кнопок/путей, пользовательских ассоциаций,
  существующих артефактов и диапазонов байтов прошли.
- В отдельном тестовом окне из исходников открыт фактический `preview.mp4`:
  1920×1080, длительность контейнера 5,013333 с, `readyState = 4`.
  Воспроизведение и перемотка на 4 с прошли без ошибки декодирования.
  Звук во время автоматической проверки был выключен; прослушивание не заявляется.
- Проверка плеера не отправляла медиа внешним моделям и не вызывала платный API.

После новой установки можно открыть прежний ответ: абсолютный путь к ролику
должен отображаться как кнопка. Перегенерировать видео для проверки плеера не нужно.
