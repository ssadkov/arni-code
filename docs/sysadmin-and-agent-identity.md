# Сисадмин: первая проверка компьютера

20 октября 2026. Реализованы профиль «Сисадмин», навык `computer-check` 1.0.0 и готовый Python-помощник. Это диагностический сценарий, без очистки, отключения автозагрузки и установки программ. На вопрос «что умеешь?» профиль объясняет возможности без сканирования; команда помощника `capabilities` тоже не собирает сведения.

## Что проверяется

- Модель компьютера, производитель, версия ОС, архитектура, CPU и ядра, объём ОЗУ, названия GPU.
- Размер и свободное место фиксированных логических дисков Windows; системного/Data-томов macOS. Служебный виртуальный том не равен физическому SSD. APFS может разделять свободное место между томами: их свободную ёмкость не суммируют.
- Восемь процессов с наибольшим потреблением памяти, без аргументов команд. Это снимок, не проверка утечек и не доказанная причина тормозов.
- Windows: Win32_StartupCommand и доступные задачи с Boot/Logon-триггерами. Наличие StartupCommand не доказывает, что запись включена. Современные регистрации запуска, все пользователи/службы и StartupApproved не покрыты полностью.
- macOS: ограниченный набор пользовательских/общих LaunchAgents и системных LaunchDaemons; состояние loaded проверяется только в текущем пользовательском домене launchctl. Plist Disabled не используется как доказательство текущего состояния. Современные Login Items/фоновые регистрации и другие пользователи остаются отдельной ручной проверкой.

Каждый источник имеет статус и границы покрытия. Недоступное не подменяется пустым списком. Каждая команда имеет timeout; количество записей ограничено. Нет автоматического повышения прав, AppleScript с запросом Automation, сетевых запросов, полного сканирования файлов и выполнения найденных команд автозапуска.

Помощник требует рабочий Python 3; FFmpeg и дополнительные Python-пакеты не нужны. На чистом Mac Python может отсутствовать или быть заглушкой Command Line Tools. Навык тогда предлагает ограниченные встроенные команды для CPU/ОЗУ/диска или отдельную согласованную установку Python; не устанавливает его в рамках диагностики.

## Приватность и отчёт

Сырые CIM/system_profiler используются только внутри локального помощника. В JSON попадают выбранные свойства: не собираются поля серийного номера, имени владельца/хоста, аргументы процессов и содержимое документов. Домашние пути, email и UUID в строках маскируются. Это не анонимизация: имена приложений/служб и характеристики могут идентифицировать устройство или содержать личные сведения. При чтении JSON выбранная LLM получает этот сокращённый отчёт; пользователь должен знать об этом до проверки.

По умолчанию результат идёт в stdout. `check --output <новый-файл.json>` сохраняет только новый отчёт и не перезаписывает существующий файл. Рекомендация по освобождению места не означает, что что-либо удалено; флаг малого остатка означает менее 10% свободно. Температуры, SMART, вирусы, дубликаты, крупнейшие личные файлы и автоматическая очистка в первой версии не реализованы.

## Проверка и запуск

`python scripts/test-computer-check.py` проверяет Windows/macOS fixtures, исключение частных полей, ошибки/таймауты, состояние launchd, режим описания и запрет перезаписи. `ARNI_TEST_NATIVE=1` добавляет фактическую проверку ОС запуска. На этом Windows проверены все семь тестов и настоящий отчёт: определены CPU/ядра, ОЗУ/GPU, два логических тома и оба источника автозагрузки; сбор занял около пяти секунд. Это наблюдение этого компьютера, не обещание скорости. CI [Computer check smoke #39478555133](https://github.com/ssadkov/arni-code/actions/runs/39478555133) успешно прошёл на windows-latest и macos-latest. Это нативная проверка помощника на CI, отдельно от GUI-теста на MacBook Air M4 Александра.

Настоящий SDK с локальной синтетической моделью загрузил четыре русских профиля, включая «Сисадмин», и полный текст `computer-check` до ответа модели. Платных запросов для проверки не было. Это проверка загрузки, не утверждение, что реальная бесплатная модель уже прошла весь пользовательский сценарий.

Каталог теперь содержит 14 навыков, четыре профиля и 25 файлов. Экспорт подготовлен в backend, но исходники/PR и развёрнутый каталог — разные состояния. Для текущего клиента 1.0.11 можно открыть изолированную тестовую папку с `.github/agents/sysadmin.agent.md` и `.github/skills/computer-check`. После развёртывания каталога: F1 → «Арни: Обновить библиотеку навыков», перезагрузка окна, новый чат, выбор «Сисадмин». Запросы: «Что умеешь?» и «Проверь компьютер. Покажи характеристики, свободное место и доступную автозагрузку. Ничего не меняй». Переустановка клиента для markdown/Python-навыка не требуется.

## Иконки и участие в диалоге — локальный интерфейс 21 октября

Добавлены иконки вместе с видимыми именами в переключатель профессий: Сисадмин — инструменты, Монтажёр — видеокамера, Секретарь — блокнот, Контент-редактор — редактирование. Выбранная профессия помечается текстом «Выбран». Пользовательские неизвестные профили сохраняют прежнее отображение; изображения-аватары пока не добавлены.

Над ответом показывается «Отвечает:» с именем/иконкой. Роль берётся из сохранённого запроса конкретного хода, а при восстановлении истории — из его agent URI. Переключатель текущего чата не переименовывает старые ответы. Неизвестная старая роль не угадывается. Для четырёх встроенных профессий используется стабильное имя файла; это обозначение профиля, а не доказательство работы отдельной модели или отдельного процесса.

У последнего ответа показывается «Участвовали в диалоге:», когда известных участников больше одного. Основной профиль учитывается после появления текста, размышления или инструмента, подагент — только после provider-reported startedAt. Пустой ответ, терминальная команда, упоминание профессии в тексте или ещё не запущенный подагент участием не считаются. Имена видимы без различения цвета, декоративные иконки скрыты от screen reader.

Проверка: 211 Electron-тестов прошли (один ранее пропущенный), включая настоящий DOM переключателя, очистку переиспользованных строк и восстановление разных профессий по ходам; проверка типов изменённых файлов — без ошибок; ESLint и diff-check — без ошибок. Устаревшее ожидание английской строки в тесте ask-user приведено к текущему русскому тексту.

Для теста открыт отдельный локальный preview с копией авторизации и изолированным профилем, проектом sysadmin-test. Изменённые модули интерфейса собраны из текущих исходников. Неизменённые встроенные расширения восстановлены из установленной 1.0.11 после сбоя локальной сборки media-расширений (отсутствовал esbuild); их исходники совпадают. Это локальная проверка интерфейса, не опубликованный установщик и не развёрнутый backend-каталог. Установленный клиент и его профиль не заменяются.

Живой GUI-тест: в отдельной папке вне Git бесплатная NVIDIA Nemotron 3.5 Super VL ответила на вопрос «Что умеешь?» по профилю Сисадмина за 8 секунд. Usage: 55 257 входных токенов, 184 cached input, 154 выходных; тариф модели $0/$0. Диагностические команды не запускались. Видны имя/иконка автора ответа. Первый пробный проект внутри репозитория унаследовал его инструкции разработчика; тест остановлен, итоговый проект перенесён за пределы репозитория. Для системной диагностики используйте отдельную папку без AGENTS.md разработки.

## Доработка навыка после живого теста — 1.0.1

21 октября: первый отчёт соответствовал данным, но свободный разбор автозагрузки выдал неподтверждённые советы, неверные объяснения программ и обещание экономии RAM. Вместо обхода помощника серией команд обновлены навык, профиль Сисадмина и его read-only сборщик:

- Шесть ограниченных источников StartupApproved возвращают только имя, область и первый байт состояния. Подсказки enabled/disabled не являются доказательством реального запуска; код 1 и неизвестные значения остаются unknown. Отсутствующий ключ, отказ в доступе и усечённая выдача различаются. Одинаковые имена из разных источников не склеиваются автоматически.
- В именах маскируются Windows SID; stdout использует компактный ASCII JSON. На этом компьютере проверка заняла 4,28 секунды, отчёт — 9 198 байт, получено 16 отметок. Это измерение текущего запуска, не гарантия скорости/размера.
- Сокращённый отчёт получает выбранная LLM. Отсутствие сети у Python не распространяется на весь AI-сценарий. Навык требует объяснить это до проверки.
- Пустой stdout при exit 0 остаётся непроверенным результатом. Допустима одна целевая повторная попытка доставки; затем ограничение сообщается пользователю, без цикла импровизированных команд. Проблема доставки вывода в терминальном runtime здесь не исправлялась.
- Для рекомендаций используются факт, неопределённость и возможное действие. Нельзя обещать экономию памяти без замера, считать отсутствующий процесс отключённой автозагрузкой или назначать приложению системную/обязательную роль по имени. Проверенные примеры и трактовки вынесены в references/startup-review.md.

Проверка: все 10 Python-тестов прошли, включая native Windows, области/лимиты StartupApproved, неизвестные коды, недоступные источники, маскирование SID и JSON round-trip. Валидатор skill-creator прошёл. Новый каталог содержит 26 файлов; контрольные суммы и клиентский парсер проверены. Mac-реализация не менялась; новый запуск CI отделён от ранее прошедшего Mac-теста. Новый ответ реальной модели по этим инструкциям пока не проверялся.

Навык и профиль обновлены в локальной тестовой папке вне Git; нужен новый чат в sysadmin-test, чтобы не продолжать старые предположения из истории. Обновлён и каталог backend в draft-ветке; production-каталог и установщик не выпускались.
