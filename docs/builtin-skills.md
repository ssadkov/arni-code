# Встроенные скиллы Arni: первая версия

Скилл — инструкция с исполняемыми помощниками и критериями проверки результата. Модель выбирает действия и оценивает результат; повторяемую механику выполняет проверенный код. Скилл не гарантирует правильную визуальную оценку и не заменяет разрешения инструментов.

## Зависимости и первый тест на Mac (кандидат 1.0.5)

Скилл 1.0.2 добавляет команду `doctor`: проверка Python, ffmpeg, ffprobe, нужных фильтров и кодеков; JSON с путями/версиями/причинами; ненулевой код при проблеме. Если Python отсутствует, агент сначала проверяет интерпретатор средствами оболочки. Отсутствующие программы не устанавливаются самой командой: инструкция предлагает установку, учитывает уже данное согласие, затем повторяет проверку и продолжает исходную задачу. Особенности macOS/Finder PATH и Homebrew описаны в references/setup.md, который также проверяется в пакете. Homebrew/Command Line Tools могут потребовать действий пользователя. Python и FFmpeg не входят в дистрибутив Arni; обещать полностью автономную установку нельзя.

Mac-сборка дополнительно выполняет doctor и реальный синтетический FFmpeg-тест на обеих архитектурах до подписи и notarization. Это проверяет обработку и упаковку, но не заменяет первый GUI-тест и установку зависимостей на чистом пользовательском Mac.

## Хранение и подключение

- Источник общих скиллов: `src/vs/sessions/skills/<name>/SKILL.md`. Скрипты лежат рядом в `scripts/` и поставляются с приложением. Код и инструкции версионируются в Git.
- `AgenticPromptsService` обнаруживает встроенные скиллы; существующий механизм кастомизаций передаёт их в SDK. Сначала доступны имя/описание, полная инструкция загружается при использовании.
- Локальный скилл пользователя/проекта с тем же именем имеет приоритет над встроенным. Например, команда может хранить свой вариант в `.github/skills/greenscreen-preview/SKILL.md` в проекте.
- В первой версии нет нового облачного каталога, синхронизации скиллов компании, управления ролями сотрудников или отдельного магазина. Это следующие этапы; существующее окно кастомизаций и явное указание имени скилла используются сейчас.
- Медиа-помощник пишет имя/версию скилла в события прогресса, `manifest.json` и `report.json`. Агент должен назвать использованную версию в ответе. Отдельные бейджи версий в интерфейсе ещё не реализованы.

## greenscreen-preview 1.0.1

Кейс: один ведущий на зелёном фоне, новая фоновая картинка, короткий предпросмотр. Требуются установленные Python 3, FFmpeg и ffprobe. Новые зависимости в приложение не устанавливаются. Сеть/API внутри помощника не используются.

1. `prepare`: ffprobe исходника; три уменьшенных кадра; измерение зелёного цвета на краях; шесть вариантов ключа на одном кадре; таблица композиций и масок; измерение удаления зелени и непрозрачности центральной области.
2. Агент смотрит исходники и варианты. Численные проверки — эвристики, не полноценная сегментация человека. Цвет одежды/позиция ведущего/свет могут потребовать другого метода.
3. `render`: выбранные параметры; уменьшение разрешения перед ключом; прозрачные поля без обрезания ведущего; зацикленный фон; despill; исходный звук; квадратные пиксели; максимум десятисекундный отрывок.
4. Проверки длительности видео, числа кадров, звука, размера, SAR; полное декодирование короткого результата; три кадра, сравнительная таблица и крупный центральный фрагмент. Технический успех всегда остаётся `visual_review_required` до просмотра агентом.
5. По умолчанию — один предпросмотр и максимум одна коррекция, полный ролик только по запросу. Старые результаты и исходники не перезаписываются. Сохранённая копия `reproduce.py` и JSON аргументов воспроизводят запуск.

Терминал получает короткий JSON-прогресс, FFmpeg stderr сохраняется в файл. Ошибка процесса даёт ненулевой код, отчёт об успехе не создаётся. Модель не должна переписывать помощник при подборе параметров.

## Как повторить тест в обновлённой Arni

Новый чат в `C:/work/test_qwen_api`, модель Nemotron 3.5 Super VL free. Введите `/greenscreen-preview` и выберите одноимённую подсказку: вызов проверен в интерфейсе. Затем допишите задачу. Навык также виден в Customizations → Skills → Built-in. Для сравнения с платной — другой новый чат и новая папка вывода, тот же запрос:

```text
Используй встроенный навык greenscreen-preview.
В проекте source.mp4 и background.jpg. Замени зелёный фон и сделай только
пятисекундный горизонтальный предпросмотр 1920x1080 с исходным звуком.
Сохрани результат в новой папке output/skill-free-01; если занята, выбери следующий номер.
Сначала подготовь и сам посмотри варианты одного кадра и выбери настройку,
которая сохраняет человека. Затем создай предпросмотр, проверь отчёт,
посмотри сравнительные кадры и крупный фрагмент волос и плеч.
Допускается одна коррекция. Полный ролик не рендери, исходники не меняй.
Сообщи использованную версию навыка, фактическое время рендера, проверки и дефекты.
```

Сравнивать: успех инструмента; видимое качество; соответствие оценок модели изображениям; число запросов; стоимость из серверной истории. Локальное время рендера не равно полному времени агента и не определяет API-стоимость.

## Проверки перед выпуском

- `scripts/test-powershell-sentinel.mjs`: настоящий Windows PowerShell 5.1, cmdlet/ошибка синтаксиса/исключение/нативная ошибка после успешного вывода/устаревший LASTEXITCODE/Unicode/сохранение переменных.
- `scripts/test-greenscreen-skill.py`: синтетическое видео с ведущим-прямоугольником и звуком; фон заменён, центральная область непрозрачна, технические проверки проходят; исходник не меняется; перезапись запрещена; ошибочный процесс не создаёт отчёт об успехе.
- `verify-billing-package.mjs`: SKILL.md и помощник включены в пакет, их SHA-256 записаны в манифест сборки.
- Реальный исходник и независимый запуск через агента — отдельные проверки, не заменяются синтетическим тестом.
