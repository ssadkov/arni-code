# Подпись кода для Windows (Azure Trusted Signing)

Данный документ описывает процесс настройки цифровой подписи (Code Signing) для приложения **Arni Code** на платформе Windows, чтобы устранить предупреждения **Windows SmartScreen** («Система Windows защитила ваш компьютер») и UAC («Неизвестный издатель»).

---

## 1. Как устроена оплата ($10/мес или разово?)

В сервисе **Microsoft Azure Trusted Signing**:
* **Модель оплаты:** Подписка Azure с ежемесячным списанием (тариф *Basic* стоит **~$9.99 в месяц** за активный профиль сертификата).
* **Срок действия уже подписанных файлов:** **Бессрочно.**  
  При каждой подписи обязательно ставится криптографический штамп времени (*Timestamp* через сервер `http://timestamp.acs.microsoft.com`). Благодаря этому Windows всегда знает, что файл был подписан в период действия профиля. Даже если через полгода вы отключите сервис, **ранее выпущенные версии приложения останутся доверенными навсегда**.
* **Нужно ли платить каждый месяц?**
  * **Да, если вы регулярно выпускаете обновления:** Каждый новый `.exe` инсталлятор или обновление требует наложения новой цифровой подписи в момент сборки.
  * **Можно ли отключить?** Верификация юрлица (*Identity Validation*) привязывается к аккаунту и действует до 3 лет. Технически профиль подписи можно удалить после релиза и создать заново перед следующим крупным релизом, но для активного проекта проще держать ресурс активным (~$120/год — это в 3–5 раз дешевле классических EV-сертификатов от DigiCert/Sectigo, где сразу требуют от $400 до $700 в год).

## 2. Подготовка со стороны ТОО (Казахстан)

### 2.1. Получение D-U-N-S номера
Microsoft и верификационные службы идентифицируют компанию по международному номеру D-U-N-S (Dun & Bradstreet).

1. Проверьте, есть ли уже номер у вашего ТОО, на [dnb.com](https://www.dnb.com/).
2. Если номера нет — подайте бесплатную заявку на регистрацию D-U-N-S:
   * Потребуются: БИН, официальное наименование ТОО на английском языке, юридический адрес, ФИО руководителя.
   * Стандартный срок выдачи: от нескольких рабочих дней до 2 недель.

### 2.2. Требования к компании
Перед подачей заявки в Azure убедитесь, что готовы:
1. **Справка о государственной регистрации юрлица** (с портала eGov.kz с актуальной датой).
2. **Корпоративный сайт:** Рабочий сайт на собственном домене (например, `.kz` или `.com`), где в разделе контактов/подвала указаны реквизиты ТОО (БИН, адрес, телефон).
3. **Корпоративная почта:** Почта на домене компании (например, `dev@yourcompany.kz`). Почты на публичных сервисах (`@gmail.com`, `@mail.ru`) не принимаются.
4. **Телефон компании:** Номер с кодом Казахстана (+7 7XX...), на который доступен звонок для верификации (Callback verification).

## 3. Настройка в Azure Portal

1. **Регистрация подписки:**
   * Войдите в [Azure Portal](https://portal.azure.com) под корпоративной учетной записью.
   * Привяжите бизнес-карту казахстанского банка (Visa/Mastercard) для оплаты.

2. **Создание ресурса Trusted Signing Account:**
   * В поиске найдите **Trusted Signing Accounts** -> **Create**.
   * Выберите группу ресурсов и регион (например, `West Europe`).
   * Задайте имя аккаунта (например, `arni-code-signing`).

3. **Верификация организации (Identity Validation):**
   * В созданном ресурсе откройте вкладку **Identity Validations** -> **Add**.
   * Тип: **Organization**.
   * Заполните юридические данные ТОО (наименование, БИН, D-U-N-S, адрес, контактное лицо).
   * Дождитесь прохождения автоматической или полуавтоматической проверки (обычно 1–3 рабочих дня).

4. **Создание профиля сертификата (Certificate Profile):**
   * После подтверждения организации откройте вкладку **Certificate Profiles** -> **Add**.
   * Профиль: **Public Trust** (для распространения общедоступного ПО под Windows).
   * Имя профиля: например, `ArniCode-PublicRelease`.

## 4. Интеграция подписи в сборку Arni Code

Для автоматической подписи артефактов на сборочной машине (Windows) используется стандартная утилита `signtool.exe` совместно с модулем расширения от Microsoft.

### 4.1. Установка утилиты
```powershell
dotnet tool install --global Azure.CodeSigning.Dlib
```

### 4.2. Конфигурационный файл (`metadata.json`)
Создайте конфигурационный файл:
```json
{
  "Endpoint": "https://weu.codesigning.azure.net/",
  "CodeSigningAccountName": "arni-code-signing",
  "CertificateProfileName": "ArniCode-PublicRelease"
}
```

### 4.3. Команда подписи
```powershell
signtool.exe sign /v /fd SHA256 /tr http://timestamp.acs.microsoft.com /td SHA256 /dlib "Azure.CodeSigning.Dlib.dll" /dmdf metadata.json "path\to\ArniCode-Setup.exe"
```

### 4.4. Точки встраивания в проекте
В репозитории за упаковку дистрибутива Windows отвечают:
* `build/gulpfile.vscode.win32.ts` — параметры вызова Inno Setup (`ISCC.exe`).
* `build/azure-pipelines/common/sign-win32.ts` — скрипт вызова утилиты подписи для бинарников.

## 5. Временное решение до оформления сертификата

Пока сертификат оформляется, для тестировщиков и внутренних пользователей доступны быстрые способы обхода предупреждения SmartScreen:

1. **Снятие метки Mark of the Web (MOTW):**
   ```powershell
   Unblock-File -Path ".\ArniCodeSetup.exe"
   ```
   Или через GUI: Правый клик по `.exe` -> **Свойства** -> внизу вкладки «Общие» отметить **«Разблокировать»** -> **ОК**.
2. **Экран SmartScreen:** Нажать ссылку **«Подробнее» (More info)** -> кнопка **«Выполнить в любом случае» (Run anyway)**.
