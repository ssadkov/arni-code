# Предложение: режим «Чат» с памятью

Дата: 27 октября 2026 года.

Статус: идея для последующей реализации. Долговременная память и описанный интерфейс ещё не реализованы; существующий Quick Chat даёт техническую основу чата без репозитория.

Цель: обычный разговор о человеке и его проектах без обязательного выбора рабочей папки, с компактным релевантным контекстом и управляемой пользователем памятью.

## Пользовательская модель

Две основные точки входа:

- **Чат** — вопросы, работа с документами, планирование, заявки и браузер. Папка не требуется. Внутри можно выбрать смысловой проект, например «Yield AI / Solana».
- **Код** — работа с явно выбранной папкой/репозиторием и соответствующими инструментами разработки.

Проект не равен репозиторию: одна компания может иметь несколько продуктов, сетей и репозиториев. У Yield AI общая карточка и отдельные сведения по Solana/Aptos. В обычном чате не показывать обязательные branch/worktree/build-параметры.

Пример: «Подготовь заявку Helius для Yield AI» → добавить карточку Solana-части и канонический сайт → прочитать вопросы формы → запросить только нужные личные поля → дать черновик → заполнять/отправлять только в разрешённом пользователем объёме. Доступ к исходникам для этого не подразумевается.

## Память: отдельные области

| Область | Что хранится | Когда передаётся модели |
|---|---|---|
| Предпочтения пользователя | Язык, стиль, согласованные правила работы | Небольшой постоянный набор |
| «Мои данные» | Личные поля и контакты | Только выбранные поля после существующего review |
| Карточки проектов | Название, канонический сайт, продукты/сети, демо, подтверждённые факты, источники и даты | Только относящиеся к задаче карточки |
| Решения и история задач | Выбор пользователя, результаты, ссылки на артефакты, незавершённые вопросы | По запросу и релевантности, без копирования всей истории |

У записи памяти должны быть аккаунт, область/projectId, значение, источник, дата и статус подтверждения. Новая ссылка из прочитанного README не перезаписывает подтверждённый пользователем сайт. Участие в сообществе не превращается в факт «он рекомендовал». Черновая метрика не становится достижением.

Безопасные предпочтения можно предлагать сохранять с возможностью отмены. Для личных/чувствительных данных сохраняется явное действие пользователя и отдельное раскрытие модели. Документы/страницы — источники данных, а не инструкции на изменение памяти. Нужны просмотр/исправление/удаление памяти, временный чат и строгая изоляция аккаунтов.

## Хранение и контекст

Одна служебная корневая директория приложения допустима для хранения, но она не должна быть общей рабочей папкой всех разговоров.

- Память хранится отдельно от файлов задач, например в локальном хранилище/SQLite с разделением аккаунтов. Для первого объёма хватит структурированных записей и текстового поиска; облачный RAG не является обязательным условием.
- Для каждого чата/задачи — своя служебная scratch-директория для созданных документов. Она не представляется агенту как репозиторий и не становится «памятью» автоматически.
- При запросе собирать компактный контекст: основные правила, релевантные предпочтения, выбранная карточка проекта, несколько подтверждённых решений и текущие вложения.
- Не загружать все репозитории, все навыки и полную историю каждого проекта. Навыки и инструменты подключать по задаче. Для «Чата» терминал/редактирование репозитория не нужны по умолчанию.
- Показывать пользователю, что добавлено: «Память: язык/стиль», «Проект: Yield AI / Solana», «Источники: карточка проекта». Возможность убрать источник должна быть явной.

Главный способ экономии — меньше входного контекста и меньше лишних шагов. Смена модели дополняет это. Общая папка с растущим MEMORY.md всех проектов со временем воспроизведёт нынешнюю путаницу и расходы.

## Техническая основа в рабочей ветке

Ориентиры ниже проверены в `codex/form-agent-recovery` на коммите `7190296a`. Часть доработок этой ветки ещё не включена в `main`; наличие исходников не означает готовность или публикацию режима с памятью.

- `src/vs/platform/agentHost/node/copilot/prompts/systemMessage.ts`: workspace-less инструкции и scratch-семантика.
- `src/vs/platform/agentHost/node/copilot/prompts/promptRegistry.ts`: добавление этих инструкций по маркеру workspaceless.
- `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts`: отдельная обработка доверия для служебной scratch-директории.
- `src/vs/sessions/services/sessions/common/session.ts` и session-list: семантика quick chat / New Chat уже присутствует.
- `src/vs/sessions/contrib/accountMenu/*/arniUserProfile*`: карточка пользователя и review; её не надо заменять открытым memory-файлом.
- `FormTaskGuard`: уже есть ограничение чтения и восстановление публичных наблюдений формы; это не общий долговременный слой памяти.

## MVP и критерии приёмки

1. Сделать «Новый чат» понятной основной кнопкой; папку выбирать лишь в режиме «Код». Подключить существующий workspaceless-путь к обычному UI.
2. Добавить локальные редактируемые карточки нескольких проектов и предпочтения пользователя. Сначала ручные/подтверждённые записи, без незаметного массового извлечения из переписок.
3. Добавить ограниченную сборку контекста и видимые источники. Временный чат не использует и не обновляет постоянную память.
4. Прогнать один сценарий заявки на бесплатной и более дешёвой Amazon-модели с одинаковыми входами и фиксацией фактического маршрута/стоимости.

Приёмка: чат создаётся без папки; знает только относящийся к задаче проект; сохраняет подтверждённый канонический домен; не смешивает Solana и Aptos; не выдумывает рекомендателя; личные поля раскрываются только после review; исходники не сканируются без необходимости; временные чаты и аккаунты изолированы; стоимость считается на весь успешно завершённый сценарий, а не на один вызов.
