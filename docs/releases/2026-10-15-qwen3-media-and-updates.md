# Arni Code 1.0.1: модели, видеотест, расходы и выпуск

Состояние на 15 октября 2026 года. [Стабильный выпуск 1.0.1](https://github.com/ssadkov/arni-code/releases/tag/v1.0.1) опубликован; Windows-клиент установлен и запущен, пользователь подтвердил наличие Qwen3 в выборе модели. Это подтверждает каталог, но не заменяет платный запрос и проверку результата монтажа.

## Какую Qwen выбрать

Снимок подключённого каталога выпуска; фактический доступ и цену смотреть в аккаунте, доступность AWS может меняться.

| Модель | Регион в нашей маршрутизации | Контекст, токены | Изображения |
| --- | --- | ---: | --- |
| Qwen3 VL 235B A22B | us-east-1 | 262144 | Да |
| Qwen3 Coder Next | us-east-1 | 262144 | Нет |
| Qwen3 Next 80B A3B | us-east-1 | 262144 | Нет |
| Qwen3 Coder 30B A3B | us-east-1 | 262144 | Нет |
| Qwen3 Coder 480B A35B | us-west-2 | 131072 | Нет |
| Qwen3 235B A22B 2507 | us-west-2 | 262144 | Нет |
| Qwen3 32B | us-east-1 | 32768 | Нет |

Для монтажа с просмотром кадров и для вёрстки с проверкой скриншотов — **Qwen3 VL 235B A22B**. Для отдельной текстовой задачи по коду можно выбрать Coder Next. Если в истории уже есть картинки, переключение на текстовую модель может привести к отказу: проще начать новый текстовый чат. Не все модели, умеющие писать код, умеют видеть результат.

AWS принимает у этой VL-модели текст и изображения, а не исходное видео: агент извлекает кадры локально. Интернет предоставляют инструменты браузера/поиска приложения; само имя модели не даёт ей доступ к сети. [Карточка Qwen3 VL в AWS](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-qwen-qwen3-vl-235b-a22b.html).

## Как работает кэширование сейчас

- **Claude Sonnet 4.6, Sonnet 4.5 и Haiku 4.5:** включён explicit prompt caching повторяющегося префикса истории. Маркер ставится перед последним сообщением после проверки размера контекста. Текущая настройка использует стандартный TTL 5 минут; попадание в кэш зависит от совпадения префикса и условий AWS.
- **Qwen3:** в нашей интеграции explicit caching не включён. Экономию от кэша для Qwen обещать нельзя. Это утверждение о реализации Arni, а не о любых будущих API провайдера.
- Готовые ответы и результаты монтажа не переиспользуются вместо нового ответа модели. Кэш не делает весь запрос бесплатным: остаются новый ввод, вывод, а при промахе — запись префикса.
- Для подключённых Claude сохранены тарифные множители: чтение 0,1 от обычного input, запись 5-минутного кэша 1,25. Это не скидка на весь запрос. AWS `inputTokens`, cache-read и cache-write — разные группы; повторно списывать cached-токены как обычный input нельзя.
- На коротком первом запросе попадания может не быть; после длинного локального рендера 5-минутный кэш может истечь. Часовой TTL в этой версии не включён.

Живой AWS-тест подтвердил отдельные cache-write и cache-read счётчики. Описание механизма и сроков: [AWS prompt caching](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html). История запросов в базе и кэш провайдера — разные механизмы.

## Что узнали из предыдущего видеотеста

Это наблюдения предыдущего прогона, а не новый сравнительный benchmark:

1. Вертикальный результат 1080×1920 соответствовал исходному запросу пользователя. Для следующего теста нужно явно задать горизонтальный 1920×1080.
2. Прежний процесс сначала обрабатывал 4K-кадры в Python/OpenCV. Даже уменьшение входа до FHD не гарантировало быстрого полного рендера. В зафиксированном FHD-прогоне обработка и финальный ffmpeg заняли около 68 минут 13 секунд.
3. Локальный эталон `keyed-beach-1080.mp4` выглядел лучше по волосам и зелёному ореолу на просмотренных кадрах. Около 29 минут 17 секунд для эталона получены по временным отметкам файлов, а не контролируемым замером; это нельзя выдавать за точное ускорение.
4. Плохая маска/обработка границы сохраняет зелёные края; смена модели сама по себе не исправляет алгоритм. Нужны просмотр кадров и настройка параметров до полного рендера.
5. Локальный ffmpeg/OpenCV не является вызовом Bedrock. Стоимость агента зависит от числа вызовов, объёма повторяемой истории, изображений и ответов, а не просто от минут рендера. Частые платные проверки «готово ли?» не нужны для обновления UI-прогресса.
6. Общий израсходованный бюджет аккаунта не равен цене конкретного видеотеста. Для сравнения новых прогонов использовать разные чаты и их USD-историю. Старые записи без `chatId` надёжно разнести по чатам задним числом нельзя.

## Готовый промпт для первого теста

Открыть существующий проект с `source.mp4` и `background.jpg`, начать **новый чат**, выбрать **Qwen3 VL 235B A22B**. Сначала записать расход чата/аккаунта через команду «Arni: Расходы API в USD»; после теста проверить журнал того же чата.

```text
В проекте есть source.mp4 с человеком на зелёном экране и background.jpg.
Сделай новый пятисекундный предпросмотр с заменой зелёного экрана этим фоном.
Результат — горизонтальный 1920×1080 с исходным звуком и без дополнительного
обрезания человека относительно исходного кадра.

Проверь параметры исходника через ffprobe и посмотри несколько исходных кадров.
Предпочти простой быстрый pipeline ffmpeg; цвет ключа и параметры подбери по кадрам.
Если нужен другой метод, кратко объясни причину. Не повторяй старый алгоритм вслепую.
При уменьшении разрешения делай это до дорогой покадровой обработки.

Прежние скрипты, исходники и результаты сохрани. Новый скрипт/команду и результат
положи в отдельную новую папку output/qwen-vl-test-01; если она существует,
выбери следующий свободный номер. Сохрани preview.mp4 и контрольные кадры
на 0,5, 2,5 и 4,5 секунды, а также крупный фрагмент волос/плеч.

Сам открой полученные кадры и оцени зелёный ореол, края, волосы и сохранность человека.
Допускается одна корректировка параметров с повторным пятисекундным предпросмотром.
Выводи прогресс процесса в терминал; Python, если понадобится, запускай с -u.
Не делай частые циклические проверки терминала. Сообщи время выполнения,
фактический код завершения и пути файлов. Полный ролик пока не рендери:
остановись после предпросмотра и оценки качества.
```

Нативный терминал: раскрыть команду → Show Output / Focus Terminal. Процент/ETA появляются только при распознаваемом выводе процесса; ETA приблизительный. Для сравнения другого варианта начать другой чат и сохранить отдельный результат. Реальные USD брать из журнала приложения, а не из предположений модели.

## Проверки и границы готовности

- Backend: 13 Bedrock/update-feed, 17 billing и 9 media проверок; клиентские целевые тесты и проверка типов прошли.
- AWS audit profile: семь Qwen выполнили tool call и приняли его результат; VL распознала тестовую картинку; Claude показал cache-write/cache-read. Это не проверка production bearer-ключей через платный запрос из приложения.
- Windows 1.0.1: установлена, проверены CLI, 10 checksum ядра, 37 entrypoints расширений и новые компоненты; пользователь подтвердил список Qwen.
- macOS arm64/x64: Developer ID, Apple Accepted, staple/validate, Gatekeeper и CLI прошли. Все 13 release assets сверены с SHA-256 и GitHub digest/size.
- Feed: 200 для старой версии и правильной архитектуры, 200 для повторного запроса pending-коммита, 204 для текущей/более новой версии. У RU-прокси наблюдались отдельные таймауты, повтор проходил; прямой Vercel отвечал быстро.
- Платный видеотест в Arni, качество монтажа и реальный GUI install/update на Mac остаются пользовательскими проверками.

## Выпуск и восстановление

Windows runtime: `ba48e106949e0258e8e34c73456b317bc5247750`; macOS runtime: `40229563b04d260713879ee5a037bfabfd9693b9`. Backend: `c59e0d0` и follow-up `a227959`. Дальнейшие CI-исправления не меняли эти runtime-пакеты. Подробные хеши, запуски и отчёт: [arni-next-update.md](../arni-next-update.md).

Уроки упаковки: stable Windows AppX требует настроенного `win32ContextMenu`; P12 из Windows проверять нативным импортом до тяжёлой сборки; повторы сетевых ошибок Apple должны охватывать подпись, staple и validate. Подписанный ZIP сохраняется до notarization. `recover_signed_run` восстанавливает его с проверкой Team ID, исходного commit и архитектуры без компиляции. Проверки подписи/Apple не отключаются ради выпуска.

Секреты подписи хранятся в GitHub Secrets. Сертификат текущего выпуска действует до 2027-02-01; новые выпуски после истечения требуют обновления сертификата. При публикации заранее собранных assets следить за tag-triggered duplicate builds: они не должны перезаписывать уже проверенные файлы. Старым Mac-клиентам нужна одна ручная установка DMG; Windows auto-update feed в этой версии не реализован.
