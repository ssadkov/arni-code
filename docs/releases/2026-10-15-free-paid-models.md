# Обновления 1.0.2–1.0.3: бесплатные и платные модели

## Зачем

Один аккаунт должен выбирать бесплатную vision-модель и платную модель непосредственно в приложении. Смена провайдера администратором больше не должна быть частью обычного сценария.

## Изменения

- Backend объединяет разрешённые Bedrock-модели и OpenRouter; маршрут определяется выбранным ID, а не общей настройкой провайдера аккаунта. Сервер проверяет каталог и доступы.
- Бесплатные варианты проходят проверку нулевой цены, имеют отдельные бесплатные шаги и не занимают денежный резерв. Исчерпанный, отключённый или просроченный API-бюджет не блокирует их.
- PNG/JPEG доступны vision-моделям обоих провайдеров. Fallback бесплатной модели ограничен бесплатными кандидатами с поддержкой изображений, если запрос их содержит.
- Платные запросы сохраняют резервы и расчёт по фактическому USD cost OpenRouter. Для резерва учитываются опубликованные ценовые уровни и ставки image/cache; отсутствие точной стоимости помечается estimated.
- Кэш OpenRouter: сервер добавляет маркер стабильного текстового префикса только для документированных явных вариантов. Поле `cache_write_tokens` нормализуется в единый учёт. Для Bedrock Claude сохраняется прежняя реализация.
- В заголовке программы: email, API-бюджет и бесплатные шаги. В меню: тариф, состояние бюджета и расходы последнего активного чата. Тариф FREE и отдельно выданный бюджет отображаются раздельно.
- Модели показывают признаки оплаты, изображений и поддержки кэша. Признак кэша означает возможность, а реальное попадание подтверждается только счётчиками usage.
- Инструкции агента требуют реального просмотра кадров, проверки видеодорожки/числа кадров и воспроизводимого скрипта. FFmpeg следует вызывать с коротким диагностическим выводом; полный журнал остаётся в терминале/файле.
- PowerShell fallback выдаёт числовой sentinel и после cmdlet без LASTEXITCODE.

## Порядок испытаний

Каждый тест — новый чат в одном проекте, исходники неизменны, результаты в новой папке. Не продолжать старый неудачный чат Qwen: накопленная история исказит сравнение стоимости.

1. Бесплатные vision-модели: `google/gemma-4-31b-it:free`, `nvidia/nemotron-3.5-super-vl:free` (если остаются в текущем каталоге).
2. Дешёвые платные vision: `google/gemini-2.5-flash-lite`, затем Qwen3 VL через OpenRouter для сравнения с Bedrock.
3. Кэш: `anthropic/claude-haiku-4.5` для визуального цикла; `qwen/qwen3-coder-flash` для текстового кодинга. Проверять cache write первого и cache read последующего запроса, их стоимость и итог всей задачи.
4. Лендинг: одинаковое ТЗ, просмотр страницы на широком и узком экране, исправление по скриншотам.
5. Формы: тестовая форма, заполнение, проверка обязательных полей; финальная отправка только при соответствующем разрешении пользователя.
6. Простое приложение: одинаковая задача, запуск, сценарий пользователя и визуальная проверка.

Для видеотеста успешность: 5 секунд видеоряда, около 125 кадров при 25 fps, исходный звук, сохранённый человек, изменённый фон; просмотр кадров 0.5/2.5/4.5 с волосами и плечами. Код выхода 0 недостаточен.

Сравнивать качество, подтверждённые просмотры изображений, время всей задачи, число вызовов, токены/кэш и итоговый USD расход. Локальный рендер FFmpeg не является платным API-вызовом.

## Как повторять тест в программе

Открыть проект с `source.mp4` и `background.jpg`, создать новый чат, нажать название модели под полем ввода и найти нужный ID. Для перехода с платной на бесплатную достаточно выбрать вариант с `:free`; административная смена провайдера не нужна. Для честного сравнения следующую модель проверять в новом чате, иначе она получит накопленную историю предыдущей.

Для ближайшего теста начать с Nemotron 3.5 Super VL free: в проверках 15–16 октября общий пул Gemma 4 31B free возвращал 429. Gemma остаётся альтернативой при доступном пуле. Затем Gemini 2.5 Flash Lite. Отдельно — Haiku 4.5 с проверкой cache read/write по журналу. Qwen Coder Flash использовать для текстового кодинга: изображений он не принимает.

Одинаковый промпт, меняя только имя папки результата:

```text
В проекте source.mp4 с человеком на зелёном фоне и background.jpg.
Создай воспроизводимый скрипт и только 5-секундный предпросмотр в output/test-free-01/.
Сохрани ориентацию исходника, уменьши до 1920x1080, сохрани исходный звук.
Фотография фона должна покрывать все 5 секунд. Исходники не изменяй.
Проверь, что фон в результате заменён на background.jpg. Если остался исходный зелёный фон, считай тест неуспешным.
Проверь ffprobe: видеодорожка около 5 секунд и 125 кадров при 25 fps.
Извлеки кадры на 0.5, 2.5 и 4.5 секунды и действительно открой их инструментом просмотра изображений.
Проверь волосы, плечи, зелёный ореол и сохранность человека. Допускается одна коррекция и один повторный предпросмотр.
Если инструмент просмотра недоступен, прямо сообщи, что визуальная оценка не выполнена.
Выводи короткий прогресс в терминал; полный FFmpeg log сохраняй в файл, не вставляй его в чат.
Сообщи проверенные параметры результата, фактическое время и пути файлов.
Полный ролик не рендери. Остановись после оценки предпросмотра.
```

Дальнейшие серии: лендинг с проверкой desktop/mobile скриншотов → тестовая браузерная форма → простое приложение с запуском и проверкой основного сценария. Для каждой серии фиксировать результат и всю стоимость чата, а не только цену миллиона токенов.

## Дополнительная регрессия vision, 1.0.3

После установки 1.0.2 проведена разрешённая владельцем проверка одного JPEG через реальный UI. Gemma free получила 429; сервер правильно переключил на Nemotron 3.5 Super VL free. Два вызова стоили $0. Следующая проверка Gemini 2.5 Flash Lite: два вызова, $0.003410. Обе модели сообщили о просмотре и описали изображение, однако `imageCount=0` во всех этих запросах. Поэтому эти ответы нельзя считать визуальной оценкой.

Причина воспроизведена без внешнего API на настоящем Copilot SDK и локальном HTTP mock: SDK отправляет `function_call_output.output` как массив `input_text` + `input_image`. В мосте Arni выход был описан только как строка; массив попадал в текстовый блок и бинарное изображение терялось. 1.0.3 расширяет контракт function/custom tool output до текста или multimodal-массива и переводит изображения результата инструмента в LM API data parts. Удалённые image URL не загружаются; прежняя валидация MIME/data URL сохраняется.

Добавлены регрессии обоих переходников и их запуск в Windows CI. Также округляются подписи цен, чтобы $0.10 не превращались в $0.09999999999999999. Это отдельное исправление клиента; backend и тарифы не меняются. Полноценный сравнительный видеотест проводить только после проверки ненулевого `imageCount` в исправленной сборке.

Вторая причина найдена локальным сравнением с настоящим SDK: legacy-поля `maxContextWindowTokens` / `maxPromptTokens` / `maxOutputTokens` рядом с `capabilities` приводили к потере vision при сериализации запроса. Сам handler получал валидный JPEG, а SDK отправлял только строку. Все лимиты перенесены в `capabilities.limits` (`max_context_window_tokens`, `max_prompt_tokens`, `max_output_tokens`); vision остаётся в `capabilities.supports`. Лимиты не убраны и не завышены. Принудительное включение vision для всех моделей и альтернативный `contents` не потребовались и не включены.

`node scripts/test-sdk-vision-bridge.mjs` использует реальный импортируемый SDK и установленный native runtime, фактический builder конфигурации launcher, синтетический пиксель и HTTP на 127.0.0.1. Проверяет 2 обращения и ровно 1 изображение в результате инструмента. Внешних запросов моделей и платных вызовов нет. Тест с legacy-полями воспроизвёл потерю; исправленный builder прошёл. Windows CI запускает эту проверку вместе с регрессиями переходников. Отдельно прошли 7 тестов builder, 20 тестов переходников и 20 тестов каталога/цен расширения.

Контракт изображений SDK: [GitHub image input](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/image-input). Поддержка vision и её лимиты относятся к возможностям модели; наличие текста «просмотрено» не подтверждает доставку пикселей.

### Реальная доставка картинки и отсутствие зависимости от GitHub

В авторизованном dev-клиенте, чат `e4a026f5-475c-4c64-aca4-12c71c615481`, 16 октября 01:19 Asia/Qyzylorda, сервер подтвердил `imageCount=1`, 56810 input / 290 output, cost $0. Фактическая модель `nvidia/nemotron-3.5-super-vl:free` после 429 выбранной Gemma. Модель правильно определила женщину с микрофоном на зелёном фоне и сообщила, что фон ещё не удалён. Это проверка одного существующего кадра, не монтаж видео.

Для изоляции транспорта в том прогоне отключили image upload только в QA-профиле. При включённой настройке старый prompt renderer пытался получить GitHub-сессию даже для BYOK; в dev-профиле без собранного GitHub auth extension возникал timeout до обращения к backend. Коррекция разрешает GitHub image upload только для CAPI metadata; literal BYOK URL и отсутствующая metadata используют inline-картинку. Копия endpoint для prompt renderer теперь сохраняет getter `urlOrRequestMetadata` явно. Два регрессионных случая с uploads=true и запрещённым GitHub auth прошли вместе с остальными тестами toolCalling (9/9); включены в Windows/macOS CI. Реальная стоимость исходных неуспешных Gemini-проверок включает консервативные estimated-расчёты прерванных запросов: на момент сверки $0.030749, ниже согласованного $0.05. Эти запросы не считать успешной проверкой зрения.
### Завершение ответа после image tool: runtime 1.0.84
