# Arni Lite: иллюстрации и вставка в презентацию PPTX

Дата: 16 ноября 2026 года. Версия 1.0. Дополнение к [ARNI_LITE_WINDOWS_SPEC.md](ARNI_LITE_WINDOWS_SPEC.md); всё, что там сказано про платформу, вход, цикл агента, согласие и journal, действует и здесь.

Статус: спецификация для реализации. В Lite ничего из этого ещё нет. Функция относится к этапу P1 (основная спека, 3.2 «Скриншоты/PNG/JPEG в чате») и требует готового MVP-цикла «модель → инструмент → результат».

## 1. Задача

Пользователь с открытой папкой проекта просит: «сделай иллюстрацию для слайда 3 и вставь в `deck.pptx`». Lite должен:

1. Сгенерировать картинку через backend Arni и сохранить PNG в проект.
2. Дать модели посмотреть уменьшенную копию, чтобы оценить результат (например, заметить нечитаемый текст и перегенерировать).
3. Вставить картинку в указанный слайд существующего `.pptx`, не повредив файл и не перезаписав оригинал без согласия.

Без Python, PowerShell-скриптов, установленного PowerPoint и любых внешних программ: всё делается встроенными инструментами клиента.

## 2. Что подтверждено, что оценка, что зависимость

| Утверждение | Статус и основание |
| --- | --- |
| Backend генерирует картинки | Подтверждено в коде `arni-backend` (HEAD `ad6733e`): `POST /api/images/generations`, `GET /api/images/{id}`, `GET /api/images/generations` (каталог и `enabled`). Продакшен-доступность для аккаунтов Lite НЕ проверена |
| Запрос к модели ограничен 4,5 МБ | Подтверждено 16.11.2026: в Arni Code запрос с двумя картинками в истории упал с `413 FUNCTION_PAYLOAD_TOO_LARGE` (лимит Vercel на тело функции). nginx `api.arnion.ru` пропускает до 20 МБ, но дальше стоит Vercel. Поднять лимит нельзя |
| Картинка в истории уходит с каждым запросом | Подтверждено: история Chat Completions передаётся целиком; base64 увеличивает размер на треть |
| Сгенерированный PNG весит до ~3 МБ | Подтверждено ограничением клиента Arni Code (3 000 000 байт при скачивании); типичный размер — оценка 1–2,5 МБ |
| WPF умеет декодировать PNG и кодировать JPEG на net48 | Подтверждено документацией: `System.Windows.Media.Imaging` (`BitmapDecoder`, `TransformedBitmap`, `JpegBitmapEncoder.QualityLevel`) поверх WIC, который есть в Win7 SP1. На реальной Win7 НЕ проверено |
| OpenXML SDK работает на net48 | Оценка: пакет `DocumentFormat.OpenXml` публикует `net46`/`netstandard2.0` сборки. Конкретную версию зафиксировать и проверить на G0 этой функции |
| Модель видит картинки | Зависит от модели: брать `input_modalities` из `GET /api/models`. Для модели без vision превью не отправлять |

## 3. Инструменты модели

Все пути — относительные внутри выбранного проекта, по правилам основной спеки (раздел 10, защита от выхода за корень, junction и symlink).

### 3.1. `generate_image`

| Аргумент | Тип | Правило |
| --- | --- | --- |
| `prompt` | string, 1–10 000 символов | Описание на английском (модели изображений не принимают кириллицу; это написать в описании инструмента) |
| `path` | string | Новый файл `.png`; существующий не перезаписывается |
| `kind` | `simple` \| `text` | `simple` — дешёвая иллюстрация, `text` — нужна читаемая надпись. ID моделей и цены брать из `GET /api/images/generations`, не хардкодить |
| `aspect_ratio` | enum | Из каталога; по умолчанию `16:9` |

Поведение:

1. Перед вызовом — подтверждение пользователя с ценой из каталога («Сгенерировать картинку за $0,04 и сохранить в images/hero.png?»). Это платное действие.
2. `POST /api/images/generations`, заголовки `Authorization: Bearer`, `Idempotency-Key`, `X-Arni-Chat-Id` (тот же, что у запросов модели, чтобы расход попал в диалог). Тело — `{ "prompt", "model", "aspect_ratio", "n": 1 }`, не больше 50 000 байт.
3. `Idempotency-Key` = SHA-256 от `[корень проекта, path, prompt, model id, aspect_ratio]`. Повтор с тем же ключом возвращает уже оплаченную картинку. После отправки POST не переключаться на другой backend-origin.
4. `GET /api/images/{id}` — скачать PNG, остановить чтение после 3 000 000 байт, проверить сигнатуру PNG.
5. Перед записью ещё раз проверить путь, писать с флагом «создать новый». Если запрос уже ушёл, сохранять даже после отмены turn: картинка оплачена.
6. Результат модели: текст (путь, модель, списанная сумма) и, только если модель поддерживает vision, **превью по правилам раздела 4**. Полный PNG модели не отдавать никогда.

### 3.2. `view_image`

Аргумент `path` (PNG/JPEG/GIF/WebP внутри проекта, до 20 МБ на диске). Возвращает превью по разделу 4. Для модели без vision — ошибка с объяснением.

### 3.3. `inspect_pptx`

Аргумент `path`. Только чтение. Возвращает JSON:

```json
{
  "slide_width_emu": 12192000,
  "slide_height_emu": 6858000,
  "slides": [
    { "index": 3, "layout": "Title and Content", "title": "Как работает MCP", "text_preview": "…до 300 символов…",
      "pictures": [{ "name": "Picture 4", "x_pct": 55, "y_pct": 20, "w_pct": 40, "h_pct": 60 }] }
  ]
}
```

Нужен, чтобы модель выбрала слайд и свободное место, а не угадывала. Лимит: до 200 слайдов в ответе, текст обрезается.

### 3.4. `insert_image_into_pptx`

| Аргумент | Правило |
| --- | --- |
| `pptx_path` | Существующий `.pptx` в проекте |
| `image_path` | PNG/JPEG в проекте |
| `slide` | Номер слайда с 1 |
| `placement` | `right_half`, `left_half`, `full_slide`, `background` или `box` |
| `box` | Для `box`: `x_pct`, `y_pct`, `w_pct`, `h_pct` в процентах от слайда |
| `output_path` | Необязателен. По умолчанию новый файл `<имя>-arni.pptx`; существующий не перезаписывается |

Поведение:

1. Это изменение файла: перед записью показать предпросмотр в UI (слайд, место, имя выходного файла) и получить согласие, как для `propose_file_change`. Рендер слайда в MVP функции не требуется — достаточно текстового описания.
2. Работать с копией: открыть исходник только на чтение, писать во временный файл рядом, затем атомарно переименовать в `output_path`. Оригинал не трогать. Перезапись оригинала — только отдельным явным согласием, с резервной копией `<имя>.bak.pptx`.
3. Через OpenXML SDK: добавить `ImagePart` в `SlidePart`, вставить `p:pic` с уникальным `cNvPr id`, позицией и размером в EMU. Пропорции картинки сохранять: вписать в область `placement`, центрировать. `background` — картинка на весь слайд и на задний план (первым элементом `spTree`).
4. В PPTX кладётся **оригинальный** PNG, не превью.
5. После записи открыть результат `OpenXmlValidator` и пересчитать слайды. Ошибки валидации — откатить (удалить временный файл) и вернуть `failed` с текстом ошибки.
6. Файл открыт в PowerPoint (заблокирован) — вернуть понятную ошибку «закройте файл в PowerPoint», не ждать бесконечно.
7. Результат по формату основной спеки (раздел 9.2): `output_path`, `slide`, итоговая рамка в процентах, `validation: "ok"`.

## 4. Картинки в запросе к модели: обязательные правила

Именно из-за нарушения этих правил функция падает в Arni Code; в Lite они нужны с первой версии.

1. **Превью вместо оригинала.** Любая картинка, которую видит модель, перекодируется: длинная сторона не больше 1024 px, JPEG качества 85, прозрачные области заливаются белым (иначе станут чёрными). Ожидаемый размер — 100–250 КБ (оценка). Если превью больше 600 000 байт или не декодируется — вернуть модели только текст.
2. **Бюджет тела запроса.** Перед каждым `POST /api/chat/completions` посчитать размер сериализованного JSON в байтах UTF-8. Если больше 4 000 000 байт — заменять части `image_url`, начиная с самой старой, на текст `[An image from earlier in this chat was removed so the request fits the size limit. View the file again if you need it.]`, пока не уложится. Последней удаляется самая свежая картинка. В локальной истории диалога картинки остаются; урезается только отправляемая копия.
3. **Если после удаления всех картинок тело всё равно больше лимита** — не отправлять запрос, показать пользователю «Диалог слишком длинный, начните новый» вместо ошибки сервера.
4. **Ошибка 413 от сервера** (в том числе `FUNCTION_PAYLOAD_TOO_LARGE` в тексте) — отдельное сообщение «Запрос слишком большой», без автоматического повтора того же тела. В нормализатор ошибок основной спеки (раздел 8.4) добавить этот код.
5. Хранение: превью кэшировать по пути и hash файла, чтобы не перекодировать каждый запрос.

Код перекодирования — в Windows-слое (WPF Imaging) за интерфейсом `IImageCodec`, чтобы `Core` оставался `netstandard2.0`. Подсчёт бюджета и удаление старых картинок — чистая логика в `Core`.

Эталон реализации правил 1–2 в Arni Code: `extensions/copilot/src/extension/byok/common/requestImageBudget.ts` и `_chat.createModelImagePreview` в `src/vs/workbench/contrib/chat/browser/chatImageUtils.ts`.

## 5. Системный контекст модели

Добавить в инструкции агента, когда инструменты включены:

- Картинки рисовать через `generate_image`, не пытаться писать скрипты или ставить Python.
- Перед вставкой вызвать `inspect_pptx`, выбрать свободную область.
- Если на картинке нужен читаемый текст — `kind: text`; надписи лучше делать текстом слайда, а не картинкой.
- Каждая генерация платная: одна генерация на одну картинку, без повторов той же просьбы.

## 6. Ошибки и деньги

- Ошибки бюджета от `/api/images/generations` (`five_hour_limit`, `weekly_limit`, `insufficient_budget`) показывать как в основной спеке; в цикле агента — остановиться, а не пробовать другую модель.
- `enabled: false` в `GET /api/images/generations` — инструмент `generate_image` модели не предлагать.
- Скачивание не удалось после оплаты — сообщение «повторите с тем же описанием и путём: повтор не спишет деньги второй раз».

## 7. Критерии приёмки

Автоматические тесты:

1. Бюджет запроса: три картинки по 2 МБ в истории → в отправленном теле остаётся только последняя, размер ≤ 4 000 000 байт; тело без картинок не меняется; единственная слишком большая картинка заменяется текстом.
2. Превью: PNG 1344×768 с прозрачностью → JPEG ≤ 1024 px по длинной стороне, белый фон, ≤ 600 000 байт.
3. `insert_image_into_pptx` на эталонных файлах (созданный PowerPoint 2016, Google Slides export, LibreOffice export): файл проходит `OpenXmlValidator`, число слайдов не меняется, картинка на нужном слайде, оригинал байт-в-байт тот же.
4. Повторный `generate_image` с тем же ключом не создаёт второй POST-платёж; путь вне проекта, junction и существующий файл отклоняются до оплаты.

Ручная проверка на Win7 SP1, Server 2012 и Windows 11:

5. Сценарий «сгенерируй 3 иллюстрации и вставь в слайды 2–4», затем ещё 10 сообщений в том же диалоге — ни одного 413.
6. Результат открывается в PowerPoint 2010+ и LibreOffice Impress без предупреждения о повреждении.
7. Исходный файл открыт в PowerPoint — понятная ошибка, ничего не испорчено.

## 8. Оценка и порядок

Оценка, не замер: 5–8 рабочих дней одного C#-разработчика поверх готового MVP-цикла инструментов.

1. G0 функции (1 день): OpenXML SDK и WPF JPEG на Win7/Server 2012, вставка в три эталонных файла.
2. Бюджет запроса и превью (1–2 дня) — делать первыми: они нужны и для обычных скриншотов в чате.
3. `generate_image` с идемпотентностью и согласием (1–2 дня).
4. `inspect_pptx` и `insert_image_into_pptx` (2–3 дня).

Открытые зависимости до старта: доступность `/api/images/*` для аккаунтов Lite в продакшене; передача `X-Arni-Chat-Id` для учёта расходов диалога; список vision-моделей в каталоге.
